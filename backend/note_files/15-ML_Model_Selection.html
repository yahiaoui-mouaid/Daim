1️⃣ First Question: Classification or Regression? +

The target variable y determines the problem type:

If y is…Problem TypeCandidate Models
A category / classClassificationDecision Tree, SVM (SVC)
A continuous numberRegressionRegression Tree, SVR

Examples:

  • Spam / Not Spam → Classification
  • Obese / Normal / Overweight → Classification
  • House price = $245,000 → Regression
  • Temperature = 27.4°C → Regression

So the first decision is: What am I predicting?

2️⃣ Model Families: Tree vs SVM +

Both families can handle both classification and regression:

FamilyClassificationRegression
TreeDecision TreeRegression Tree
SVMSVM / SVCSVR

They differ in how they learn:

  • Tree family → learns a series of if/else rules (splits).
  • SVM family → finds a geometric boundary or margin (hyperplane / tube).
3️⃣ Classification: Decision Tree vs SVM +

Decision Tree – choose when you want understandable rules:

  • Interpretability is important
  • Non-linear relationships and feature interactions
  • You can explain decisions as: "Income > 50k AND debt < 10k → approve loan"

SVM (SVC) – choose when geometry matters:

  • High-dimensional data (e.g., text, images)
  • Complex, non-linear boundaries (with RBF kernel)
  • Small/medium dataset size
  • Interpretability is less critical

Mental image: Decision Tree = "Which rule do I apply?" | SVM = "Where do I draw the boundary?"

4️⃣ Regression: Regression Tree vs SVR +

Regression Tree – choose when:

  • Continuous target with non-linear relationships
  • You want rule-like structure (e.g., Area > 150m² → Bedrooms > 3 → $320k)
  • Interpretability is valuable

SVR – choose when:

  • Continuous target with complex relationships
  • You want a margin-based regression ("tube" around the curve)
  • Dataset is not too large (SVR can be slow)
  • Interpretability is less important

Mental image: Regression Tree = "rules producing numbers" | SVR = "fit a function within an epsilon tube"

5️⃣ Evaluation Workflow (Don't Overuse Test Set) +

The correct approach to compare models:

  1. Split data: 80% training, 20% test (keep test untouched).
  2. Cross-validation on the training set for each candidate model.
  3. Compare metrics from CV:
    • Classification: Accuracy, F1, ROC-AUC
    • Regression: MAE, RMSE, R²
  4. Select the better model based on CV scores + domain considerations.
  5. Train final model on full training data (optionally tune hyperparameters).
  6. Evaluate once on the test set.
❌ Don't repeatedly test on the test set to choose between models — you'll leak information. ✅ Use cross-validation for selection, then final test once.
